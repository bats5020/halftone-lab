03実装のコア知見（コードレベル）

3-1. ドットサイズの正しい数式（v1の最大の誤り）

// ✗ v1（線形）— インク面積が輝度に比例せず中間調が浅くなる
r = (1 - L) * cell * 0.72

// ✓ 正解（面積補正）— 被覆面積 ∝ r² なので平方根を取る
//   Stegu・Maxime Heckel 両者が同式。全競合の中で品質差が最も出る一行
r = cell * 0.5 * sqrt(1 - L)     // または r = maxR * sqrt(coverage)

さらに サンプリングは「回転後セルの中心」で行うこと（Heckel）。ピクセル毎に読むと色境界でドットが変形する：

gridUV   = rot(θ) * (uv * res) / cellSize
center   = floor(gridUV) + 0.5
sampleUV = rot(-θ) * center * cellSize / res   // 逆回転で戻してから読む

3-3. Bayer行列は再帰生成（ハードコード不要）

// 2x2 = [[0,2],[3,1]]、以降 n→2n: M2n = [[4M, 4M+2],[4M+3, 4M+1]]
// 正規化: t = (v + 0.5) / n²   → 0..1 の排他的しきい値
// 適用:   out = step(t, L)      // 2値
//         idx = round(clamp(L + (t-0.5)/levels, 0, 1) * (levels-1))  // パレット
// GLSL閉形式（テクスチャ不要・ALUのみ）:
float Bayer2(vec2 a){ a=floor(a); return fract(a.x/2. + a.y*a.y*.75); }
#define Bayer4(a) (Bayer2(.5*(a))*.25 + Bayer2(a))
#define Bayer8(a) (Bayer4(.5*(a))*.25 + Bayer2(a))

3-4. CMYK分版ハーフトーン（「本物っぽさ」の決め手）

// 1. 分版: K = min(C,M,Y) を先に取り (GCR)、CMY を (1-K) で正規化
k = min(1-r, min(1-g, 1-b));  cmy = (1 - rgb - k) / (1 - k);
// 2. スクリーン角度（モアレ最小化の伝統値）: C=15° M=75° Y=0° K=45°
// 3. 各版を sqrt 面積則でドット化し、白から乗算合成:
out = vec3(1);
out.r *= 1 - dotC; out.g *= 1 - dotM; out.b *= 1 - dotY; out *= 1 - dotK;

3-5. 書き出しの定石

  • PNG：「作業解像度でディザ → imageSmoothing=false で元解像度へ最近傍拡大」（Dithering Studio方式）。プレビューと完全一致し、re-ditherコストゼロ
  • SVG（ディザ系）：同色の水平連続セルを1つの<rect>に統合（RLE）。背景色セルはスキップして背景<rect>1枚で表現
  • SVG（ハーフトーン系）：色毎に<g fill>グループ化＋座標2桁丸め（Shpigford方式）
  • サイズ事前表示：書き出しボタンに PNG 242KB / SVG 1.1MB のように blob サイズを事前計算して表示（Dithering Studio / Dither it! 共通の「信頼感」装置）
  • 動画：canvas.captureStream + MediaRecorder（MP4→VP9→VP8フォールバック）、GIFは gifenc。まだ誰も WebCodecs を使っていない

3-6. パフォーマンスの定石

  • 誤差拡散はシェーダ不可（逐次依存）→ CPUでOK、ただし作業解像度を絞る（Dithering Studio既定512px、Efectoも同思想）。Workerは512px程度ならコピーコストで逆に損（実装して無効化した形跡あり）
  • ベクターハーフトーンの大量ドット描画は50ms毎の時分割＋rAF継続（xoihazard）か、1つの beginPath にバッチ
  • シェーダAAは smoothstep(r-aa, r+aa, dist) with aa = fwidth(dist)
